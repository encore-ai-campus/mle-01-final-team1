# 금융 GraphRAG 골든셋 후보 판정 기준

이 문서는 `golden_set_final.jsonl`을 확정하기 전에 후보를 만들고 사람 검수하는 기준이다. 시험 배치는 본 목표 120개에 포함하지 않으며, 모든 후보는 원천 청크와 근거 ID를 함께 보존한다.

## 1. 유형 판정

| 유형 | 판정 기준 | 최소 근거 |
| --- | --- | --- |
| VECTOR | 하나의 청크만으로 답을 완성할 수 있는 사실 조회 | 답변에 필요한 청크 1개, 그래프 경로 불필요, `hop_count=0` |
| GRAPH | 엔터티 사이의 연결 관계를 묻거나 관계를 확인해야 답할 수 있는 질문 | 실제 검증된 경로, 관계마다 `(from_id, relation_type, to_id)` |
| HYBRID | 그래프 경로와 원본 청크의 수치·조건을 함께 사용해야 답할 수 있는 질문 | 실제 검증된 2개 이상 관계와 답변 청크 |

관계가 두 개 있다는 이유만으로 HYBRID로 분류하지 않는다. 질문을 관계만으로 답할 수 있으면 GRAPH이고, 관계를 따라간 뒤 금리·혜택·신청조건 같은 원문 값을 함께 확인해야 하면 HYBRID다.

## 2. 난이도와 홉 수

- `easy`: 하나의 근거 청크에서 한두 개 사실을 확인한다.
- `medium`: 하나의 청크에서 두 개 이상의 필드, 기간·금리·조건을 함께 확인한다.
- `hard`: 두 개 이상의 검증된 관계를 따라가거나, 관계와 원문 조건을 결합한다.
- `hop_count`: 실제 `graph_path`의 관계 개수다. 관계 유형 이름만 적은 경우는 홉으로 인정하지 않는다.

## 3. 근거와 안전 규칙

- `reference_context_ids`는 실제 `chunks.jsonl`의 `chunk_id`여야 한다.
- 내부 근거 ID(`EVD_*`)와 Neo4j Evidence ID는 분리한다.
- Neo4j 관계 고유 ID가 없으므로 관계 식별자는 `(from_id + relation_type + to_id)`로 저장한다.
- `graph_path_verified=false`인 경로는 GRAPH·HYBRID 후보에 사용하지 않는다.
- 원천의 `0`, `null`, `not_provided`, `unknown`은 서로 다르게 보존한다. 특히 소득 `0`을 자격 제한 없음 또는 소득 하한 0으로 임의 해석하지 않는다.
- 원천에 없는 금리·기간·혜택·신청조건을 채우지 않는다. 평균금리처럼 미제공된 값도 만들지 않는다.
- 최고금리는 사용자가 실제로 받는 확정금리가 아니라 조건 충족 시 가능한 최고값으로 표현한다.

## 4. 중복과 배치

- 질문을 공백·문장부호·대소문자를 제거해 정규화한 뒤 같은 질문을 제외한다.
- 같은 청크를 다시 사용할 수는 있지만 질문과 기대 사실이 달라야 하며, 모두 같은 원천 근거로 검증되어야 한다.
- 시험 배치는 유형별 5개를 목표로 하지만 검증된 근거가 부족하면 부족한 수량과 이유를 보고한다.
- 본 생성은 유형별 20개씩 2회, 총 VECTOR 40개·GRAPH 40개·HYBRID 40개를 목표로 한다. 시험 배치는 `included_in_final_target=false`로 기록한다.

## 5. 최종 승인 조건

자동 근거 검사를 통과하고, 사람이 질문·정답·기대 사실·근거를 승인해야 한다. GRAPH·HYBRID는 Neo4j 경로 검증도 통과해야 한다. 하나라도 충족하지 못하면 `pending`, `on_hold` 또는 `rejected`로 남기며 최종 골든셋에 넣지 않는다.
